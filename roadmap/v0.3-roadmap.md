## 0.3.1 - More UI

Tweak and enhance feedback UI.

- [ ] **Shield/Armor reduction icon**
  - Add a little UI element next to damage indicators to indicate when the player is hitting special health such as armor and barrier, and make so the way such UI is displayed let the player understand if the weapon used on such health is efficient or not.

- [ ] **Tweak kill UI**
  - I think we can squeeze out more juice out of the kill UI animation.

- [ ] **Sector Icon, prediction & settings**
  - Experiment with different icon shapes for sector location UI.
  - Add a prediction UI, so that the player can also know what will be the next sector.
  - Make the sector UI opacity configurable, and maybe more.

- [ ] **Amos location**
  - Add a UI helper that indicates where is the closest matching amos spawner when the player is low on amos on a given weapon, maybe all but fade further ones, maybe configurable too.

## 0.3.2 - More feedback

- [ ] **Time per sector**
  - Register time spent on a sector, and in transitions, like a checkpoint, and manage personal bests per such sections.
  - Probably just local pbs for now, stored in user memory, and we will eventually later branch it to DB. This will just be an experimentation step.

- [ ] **Player death animation**
  - Dying is currently a bit brutal. We can add some sound effects as well as some animation, probably a simple camera animation, when the player dies, before sending him to the result screen.

- [ ] **Bots sounds & more**
  - Add sounds to various bots events, like walking, dying, spawning, hit, etc.
  - If there's enough time for it, add a jump and airborne animation.

## 0.3.3 - AI (Scoreboard reboot)

- [ ] **Enemies looking behavior**
  - [ ] Enemies can't really be flanked currently, as they always know where the player is. Enhance that by making their vision more natural. 
  - [ ] Make them probabilistically predict the player position when unknown.
  - [ ] Flicking/snapping delay - make so bots needs to react to sudden fast movements, like sideways dash.
- [ ] **More diverse movements**
  - Add jumping and air control
  - Some clearer bots movement categories.

## 0.3.4 - (Optionnal) Game mode exp

Might not be addressed this version, it will depend on the advancement of the project at that time.

Try new way to express the game mode. Maybe an extraction based game mode, where the player starts from a place and must rejoin that place to leave, instead of a pure time gate.

Once the time gate is passed, the player won't end the run right away but would start taking heavier and heavier damages. If he dies, he loses part of his score, so he must manage that properly, and can try to surf with the risk reward of the time gate.
